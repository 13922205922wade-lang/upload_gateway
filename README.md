# 喜马拉雅有声书工具

把制作端产出的有声书套包（按章节分好的音频 + 精确时间轨道 LRC 字幕）批量上传到
喜马拉雅创作者中心。macOS 原生 GUI，本机运行，浏览器扫码登录一次即可长期复用。

---

## 快速开始

### 方式 A：双击运行（已打包好的 .app）

```bash
open ~/Documents/code/喜马拉雅有声书工具/喜马拉雅有声书工具.app
```

或直接双击 `喜马拉雅有声书工具.app`，也可以拖到「应用程序」文件夹。
包内自带 Python 运行时，**不依赖任何开发环境**。

### 方式 B：源码运行

```bash
cd ~/Documents/code/喜马拉雅有声书工具

# 1) 安装依赖（只需一次）
python3 -m venv .venv && source .venv/bin/activate
pip install playwright

# 2) 自检：验证依赖 / 套包 / 浏览器都正常
python run.py --check

# 3) 启动图形界面
python run.py
```

### 重新打包 .app（改完代码后）

```bash
./build_app.sh        # 产物：喜马拉雅有声书工具.app
```

脚本会**原地复用已有 bundle**，只覆盖源码与资源：不整包删除、不重复复制
Python 运行时，登录态 / 断点状态始终留在
`~/Library/Application Support/喜马拉雅有声书工具/`，重新打包不会丢。

### 方式 C：命令行批量（无人值守）

```bash
cd ~/Documents/code/喜马拉雅有声书工具

python run_batch_cli.py                 # 跑完整批次（断点续传）
XIMALAYA_LIMIT=2 python run_batch_cli.py   # 只跑前 2 章（冒烟测试）
XIMALAYA_PACKAGE=<套包目录> python run_batch_cli.py   # 指定套包
XIMALAYA_ALBUM="专辑名" python run_batch_cli.py       # 指定专辑
```

与 GUI 用的是**同一套上传逻辑**，每章完成后立刻写 `state/*.json`，
中断可直接重跑。日志落在 `logs/batch-<时间戳>.log`。
不指定套包时，自动取材料目录里最新的那一个。

界面操作顺序（进入「喜马拉雅」后）：

1. **选择套包** —— 启动时会在材料目录里**自动找最新的那个套包**并解析好，
   章节清单直接列出来（不需要先点「解析」）。套包目录名会随版本换名
   （`…-r0003` → `…-r0004`），所以不能写死路径；找不到时用「浏览…」手动选。
   默认搜索位置：
   - `~/Documents/code/ebook_media_docs/materials/audio`（制作端材料库）
   - `~/Downloads`、项目内 `packages/`
2. **登录喜马拉雅** —— 启动时会**自动检测**登录态：
   - 已登录 → 直接显示「已登录 ✅ 昵称」，无需任何操作
   - 未登录 → 点按钮弹出 Chrome，用喜马拉雅 APP 扫码；登录态保存在
     `~/Library/Application Support/喜马拉雅有声书工具/profiles/chrome/`，
     之后每次运行都免扫码（重新打包、挪动 .app 都不会丢）
   - 若之前开的 Chrome 窗口还开着，工具会**直接接管**那个窗口，沿用其登录态，
     不需要关窗重来
3. **专辑名** —— 默认取套包 `manifest.json` 里的 `title`。
   - 点「**选择…**」打开**可搜索的专辑选择器**：顶部搜索框输入即过滤，
     列表显示专辑名 + 已有集数，单击高亮、双击或点「确定」选中
   - 点「**检查**」确认能不能匹配上（套包名和账号专辑名往往不完全一致，
     工具会按书名片段模糊匹配）
   - 确实没有就点「**新建**」自动创建
   - ⚠️ **如果多个专辑都匹配得上，工具不会替你猜** —— 会直接拦下来让你选。
     因为账号里可能同时存在「睡前有声读物：《绿野仙踪》」和
     「Tobeart有声书 | 绿野仙踪｜剧场版｜全集」这种共同片段，
     猜错会把内容静默传到错误的专辑。
4. **可见性 / 字幕轨 / AI 合成** —— 按需设置
   - 可见性默认「私密仅自己可见」（平台默认是**公开**，工具会显式改并回读校验）
   - 字幕轨默认「lrc（双语合并）」，平台一次只收一个字幕文件，中英用 ` | ` 隔开
   - AI 合成：套包 `source.model` 记着 TTS 模型时自动默认「是」，别把合成音频误报成真人录音
5. **开始上传** —— 逐章上传，右下角实时日志 + 进度条。

## 审核分类包（oz-reviewed-category-zip/v1）

制作端从 2026-11 起还会交付「审核分类包」：一个目录，或直接一个 `.zip`。
它的 `manifest.json` 只有一个 `files[]` 清单（chapter / archive_path /
sha256 / bytes），素材是 `chNN/<zh|en>.mp3` + `chNN/<zh|en>.lrc`，
**没有** `chapters[]`、章节标题、时长、语言和插图。旧版工具会直接弹
「不支持的套包 schema」，现在会自动归一化成标准 `chapters[]`：

- 按 `files[]` 还原每章音频 / LRC 路径、字节数与 SHA-256；
- 章节标题优先借同书旧交付包（r0004）的标准标题，其次从 LRC 提取
  （「第1章 龙卷风」，或短标题「龙卷风」→ 补成「第1章　龙卷风」）；
- 语言由 category / 文件名推断（A_zh → zh-CN，A_en → en-US）；
  时长取 LRC 最后一个时间戳；「是否AI合成」沿用旧交付包的 `source.model`；
- `package_key` 是 `oz-reviewed/<book>-<category>@reviewed-<日期>`，
  与旧套包的断点状态互不混淆，不会误跳过、也不会重复计。

怎么用：

- **目录**：点「浏览…」选到含 `manifest.json` 的那个目录；
- **ZIP**：点「导入 ZIP」直接选 `.zip`，工具展开到
  `~/Library/Application Support/喜马拉雅有声书工具/expanded_packages/`
  （按 manifest 内容寻址，同一份只展开一次；不进 `.app`、不进仓库）；
- 启动时日志会提示检测到的审核包，但**默认套包仍按发布号排序（r0004 优先）**，
  不会擅自切换 —— 换套包会牵动断点续传和专辑归属，必须由你明确选择。

审核包没有插图，章节列表「插图」列显示 0 是正常的；上传链路本来就不依赖章节插图。
ZIP 里的路径会做 `../` 校验，防止压缩包把文件写到缓存目录之外。

## 它解决的问题

| 痛点 | 处理方式 |
|---|---|
| 24 集要手工点 24 次 | 批量自动上传，带间隔抖动 |
| 中断后重传会重复 | 断点续传（`state/*.json`），**只跳过确认发布成功**的章节 |
| 套包更新后被旧断点整批跳过 | 断点状态记**套包版本 + 每章内容指纹**；版本或内容变了就重传 |
| 平台里已经有这批章节 | 以**平台专辑实况**为准：同名章节自动跳过（全角/半角空格算同一章） |
| 套包目录换名后工具找不到 | 启动时在材料目录里自动发现最新的 `…-rNNNN` 套包 |
| 平台改版导致脚本失效 | 选择器多路兜底 + 语义化定位，优先按文字而非 class |
| 权限默认是「公开」 | 展开「更多设置」后显式点私密，并回读 `ant-radio-checked` 校验 |
| 权限藏在折叠面板里点不动 | 自动展开「更多设置 ∨」再操作（折叠时 radio 是 0×0，点的是看不见的模板） |
| 套包名 ≠ 账号专辑名 | 按书名片段模糊匹配，匹配依据写进日志 |
| 专辑名太多、下拉框没法搜 | 「选择…」对话框带搜索框，输入即过滤，并显示每个专辑的已有集数 |
| 多个专辑都像，工具猜错 | **不猜** —— 判定为歧义并拦下来，要求明确指定 |
| 平台一次只收一个字幕文件 | 中英合并成一个 LRC，用 ` | ` 分隔（按平台提示的格式） |
| 平台默认「是否AI合成＝否」 | 套包标了 TTS 模型就自动标「是」 |
| 平台风控（验证码/频繁） | 检测到即中止批次并提示人工介入，不硬撞 |
| 已登录却还要重新扫码 | 启动自动检测登录态；旧窗口还开着时直接接管 |
| 浏览器连接断掉 → 每章都报 connection closed | 断线自动重连并重传该章；实在接不上就**中止批次**，不再一章章空转 |
| 重新打包把登录态弄丢 | 运行期数据移到 `~/Library/Application Support/喜马拉雅有声书工具/` |

## 套包格式

工具读取制作端交付套包（schema `ximalaya-picture-audiobook/v1`）：

```
oz01a-ximalaya-zh-CN-r0004/
├── manifest.json          # 章节清单、时长、sha256、图片时间轴
└── chapters/
    ├── ch01/
    │   ├── ch01.mp3       # 音频
    │   ├── ch01.srt       # 字幕（回退用）
    │   ├── ch01.lrc       # 双语时间轨（同时间戳中英成对）
    │   └── images/        # 插图
    ├── ch02/
    └── ...
```

`manifest.json` 关键字段：

- `chapters[].audio` — 音频路径 / 字节数 / sha256
- `chapters[].bilingual_lrc` — 双语 LRC，声明 `languages: ["zh-CN","en-US"]`
- `chapters[].picture_timeline` — 插图在音频时间轴上的锚点（`start_ms` / `image_id`）
- `version` / `identifier` — 套包版本（如 `R4`）与身份标识，用于判断断点状态是否还对得上
- `reviews` — 各环节自检状态

解析时会校验文件是否存在、大小是否与 manifest 一致（可选做 sha256 全量校验）。
字段名在不同版本间有过微调（`bilingual_lrc` / `lrc` / `subtitles.bilingual`），
解析器对常见写法都认，不会因为字段名对不上就丢掉字幕。

### 套包指纹：判断"内容换没换"

套包更新（重新配音、重新出图）之后，章节 id 和标题往往**一模一样**，
只有内容变了。所以每章会算一个**内容指纹**（音频 sha256 + 标题 + 时长），
套包再算一个总指纹（manifest 哈希 + 各章指纹）。

断点续传据此判断：

| 情况 | 处理 |
|---|---|
| 状态里的套包版本 = 当前套包版本，且章节指纹一致 | 跳过（确实传过） |
| 套包版本不同 | 旧记录作废，整批重传 |
| 版本相同但章节指纹不同 | 该章重传（内容换过了） |
| 旧格式状态（没有版本、没有指纹） | 不盲目跳过，以平台专辑实况为准 |

## 双语字幕的合并规则

套包里的 LRC 是「同时间戳成对」格式：

```
[00:00.240]第1章 龙卷风
[00:00.240]Chapter I. The Cyclone
[00:03.934]多萝西住在广阔的堪萨斯大草原中央，
[00:03.934]Dorothy lived in the midst of the great Kansas prairies, ...
```

工具按时间戳分组，逐组按字符集判定语言（中日韩统一表意文字 → 中文，拉丁字母 → 英文），
再**合并成一个文件**——平台一次只接受一个字幕文件，且提示明确要求
「双语字幕请以 | 隔开」：

```
[00:00:00.240]Chapter I. The Cyclone | 第1章 龙卷风
[00:00:03.934]Dorothy lived in the midst of the great Kansas prairies, ... | 多萝西住在广阔的堪萨斯大草原中央，
```

导出到 `_work/subtitles/<章节>/`，通过上传页的「上传字幕文件」入口挂载，
平台解析后显示在「编辑字幕」框里。

## 技术要点

### 为什么用 Playwright 驱动真实 Chrome

喜马拉雅没有面向个人创作者的公开上传 API——开放平台（`open.ximalaya.com`）的
API 接入需要商务审核 + IP 白名单，个人无法申请。因此走网页上传流程。

用 `launch_persistent_context(channel="chrome")` 驱动**本机已安装的 Chrome**：
不用额外下载 Chromium，登录态天然复用本地 profile，风控识别也更低。

### 已验证的页面锚点

| 用途 | 选择器 |
|---|---|
| 上传页 | `https://www.ximalaya.com/reform-upload/page/webCenter/upload` |
| 专辑创建页 | `https://www.ximalaya.com/reform-upload/page/album/create` |
| 文件入口 | `div.webuploader-pick`（含「上传音频」）→ 捕获原生 file chooser |
| 标题输入 | `input.ant-input[placeholder='请输入声音标题']` |
| 专辑选择 | `button[class*='search-select-album-btn']` + `span[class*='album-title-text']` |
| 简介 | `window.KindEditor.instances['0']` + `textarea#soundRichIntro` |
| 字幕入口 | 「编辑字幕」模式 → `div.gen-lrc-box textarea` → **「确认提交」**按钮 |
| 折叠面板 | 文本「更多设置」（权限设置在里面，展开后 radio 才有尺寸） |
| 权限设置 | `.ant-form-item` 内 label 含「权限设置」的 `input.ant-radio-input`<br>1=私密 2=公开 3=仅好友 |
| 是否AI合成 | 同上，按选项**文字**（「是」/「否」）定位，不依赖 value |
| 协议勾选 | 含「知识产权承诺」的 label 内 checkbox（**不勾选发布按钮会禁用**） |
| 发布按钮 | `button.confirm-publish`（文字「确认发布」） |
| 成功判定 | URL 含 `uploadSuccess` 或页面出现「发布成功」 |

class 名带构建期 hash（如 `album-title-text-4EH5AG-r`），平台改版会变，
因此实现里一律用 **前缀匹配 + 文字语义**双路兜底。

> **四个容易踩空的地方**（每一个都曾导致静默失败）：
> 1. 权限 radio 在折叠的「更多设置」里，折叠时尺寸是 0×0 —— 直接点等于点了个
>    看不见的模板，平台真实可见性纹丝不动。必须先展开。
> 2. 选专辑失败时，若不把弹层关掉，它会一直盖在表单上，后面的标题/权限/字幕
>    操作全部点不动。
> 3. **字幕不是"选个文件"就完事**：必须切到「编辑字幕」→ 把文本用真实输入
>    事件写进 `div.gen-lrc-box textarea` → 再点「**确认提交**」按钮。
>    平台会把文本转成 `lrc.json` 传到对象存储，拿到路径才写进表单的 `lrcPath`。
>    只填不点确认，`lrcPath` 永远是空串，发布后**字幕就没了**。
> 4. 「确认提交」后**必须等上传完成**再发布。上传没回来时 `lrcPath` 还是空的，
>    立刻点发布就会丢字幕。工具会等 `cupload` 的 `file/blk` / `mkfile` 请求出现。
>
> 另外，antd 的双字按钮文本中间带空格（「保 存」「取 消」「确 定」），
> 用 `"保存"` 去匹配会永远匹配不到。

### 后台接口（在已登录页面内 fetch，自动带 cookie）

```
GET  /reform-upload/album/choose?page=&pageSize=&kw=
     → 列出账号可选的专辑（上传页的专辑下拉用的就是它；不用先传文件）
GET  /reform-upload/manage/album/tracks?albumId=&page=&pageSize=&order=ASC&state=1
     → 列出专辑内声音，用于上传后核对完整性与顺序
GET  /reform-upload/anchorTrack/edit?trackId=
     → 单条声音详情（标题、所属专辑、可见范围、lrcPath 字幕路径）
GET  /reform-upload/anchorWork/track/list?page=&pageSize=&keyword=
     → 全站作品列表（不限专辑）
POST /reform-upload/upload/create                ← 真正的"发布"
     payload: albumId / soundTitle / visibleCrowdType / isAiTrack / lrcPath …
POST /reform-upload/anchorTrack/update            ← 编辑已发布的声音
     payload 里同样有 lrcPath
POST /reform-upload/manage/album/track/delete   {"trackId": ...}
     → 删除一条声音（不可恢复）
```

> 字幕的存储路径在 `lrcPath`，值是一个 `fdfs.xmcdn.com/.../xxx.json`。
> 工具在发布后会抓 `upload/create` 的 payload 回读核对，
> 日志里会打印「发布参数：专辑=… 可见性=… 字幕=已带上/缺失」。

## 注意事项

- **默认可见性是「私密仅自己可见」**（平台默认是公开，工具会显式改并回读校验）。
  ⚠️ **改成公开是不可逆的**：官方帮助页原文「私密的音频之后可以再设为公开；
  但**公开的音频将不能再设为私密**」。如果发现内容有问题，只能删除重传。
  审核中的节目**可以**改可见性，改动不影响审核状态。
- **审核时长**：平台规则写「中文音频一般发布 2 小时内收到审核结果」，
  但实际受**提交量**和**新账号**影响很大 —— 一次性提交几十条会进人工复审队列，
  实测 24 条提交后第 3 天才开始放行。
  **建议分批**：每次 3–5 条、间隔几小时，能显著缩短审核等待。
- **「直接发布」默认已勾选**。不勾会切成**人工确认模式**：每章填完单停下来，
  等你在浏览器里点「确认发布」，不等就等于没传。
  ——因为**喜马拉雅没有草稿箱**：那个「继续添加」只是把条目留在当前页面，
  下一章重新加载页面就没了。这条以前把整批 24 集坑过一次。
- **「是否AI合成」按套包标注自动判定**。若你的音频其实是真人录音，
  上传前把它改成「否」。
- **字幕是独立一步**：切「编辑字幕」→ 填文本 → 点「确认提交」→ 等上传完成。
  工具已经封装好了，日志会显示「已提交字幕」和「发布参数：… 字幕=已带上」。
- **平台有风控**：上传节奏做了随机抖动，但批量大文件仍建议保留间隔（默认 12s±）。
  出现「验证码」「操作过于频繁」时工具会中止，请人工处理后重跑（断点续传会跳过已发布的）。
- **日志会落盘**到 `logs/upload-<时间戳>.log`，出问题时把那个文件发出来即可。
- **审核催办**：官方回复口径是「如果长时间没有被审核，自己私聊洗马君您的ID和节目名称」。
- **非官方工具**：遵守喜马拉雅服务条款，不批量灌水。
- 已上传章节的专辑顺序若错乱，可参考社区工具 `reorder_album.py`（调用 `changeOrder` 接口重排，无需删除重发）。

## 常见问题

**Q：点「登录」后没反应？**
工具启动时会自动检测登录态。已登录就直接显示昵称；旧窗口还开着时工具会直接
接管那个窗口，不需要关窗重来。

**Q：套包换了版本，工具还按老的上传？**
不会。断点状态里记着**套包版本**和**每章内容指纹**，版本或内容变了就不再跳过。
另外开跑前会读一次平台专辑里现有的章节，同名的自动跳过（日志会写明跳过了几章、
依据是什么）。

**Q：跑完了却显示「本次完成 0/0 章」？**
说明这批章节都被判定为"已经传过"：要么断点状态里有成功的记录，要么平台专辑里
已经有同名章节。日志里会写明跳过依据。要强制重传，就取消勾选「断点续传」；
要换成新内容，先到创作中心把旧章节删掉。

**Q：每章都报「浏览器异常：Playwright connection closed」？**
这是浏览器连接断了。工具现在会先尝试重连并重传该章；重连不上就**中止整批**
（不会一章章空转），并提示重开工具。常见诱因是工具被强制退出后留下了无头
Chrome 占着 profile —— 现在工具启动时会自动结束遗留的无头实例。

**Q：提示找不到匹配的专辑？**
点「选择…」看看账号里到底有哪些专辑。套包名和账号专辑名常常不完全一致，
工具会按书名片段模糊匹配（日志会写明匹配依据）；确实没有就点「新建」。
开跑前还会再做一次专辑自检，匹配不上会直接拦下，不会白跑一轮。

**Q：字幕没上传上去？**
看日志里有没有「✅ 已提交字幕」和「发布参数：… 字幕=已带上」。
若显示「字幕=缺失」，字幕文件在 `_work/subtitles/<章节>/`，可手工补传。

**Q：想换个账号？**
删除 `~/Library/Application Support/喜马拉雅有声书工具/profiles/chrome/`
（打包版）或项目下的 `profiles/chrome/`（源码版）即可清空登录态。
